# Rhine 产品对照清单 · M8 审阅稿

按 [REQUIREMENTS-v2.md](../../migration-to-go/REQUIREMENTS-v2.md) 核对。产品验收基准是 **Qt 版 Rhine 已做出的视觉、效果和交互，加上用户明确确认的目标**。Go + MyGo 是实现架构。Cloudy 250da6d 只用于 A 类源实现及已确认的上游回退。核对对象是本地 `smtc-source-migration/app/Qt`、Cloudy 固定快照与 `rhine-go` 的 M7 提交 `0c5b1a2`。

**用户已纠正的「我的」行为**：目标是直接打开主页。当前 QML 的 `openLibrary("created")` 是未完成的接线，不能作为目标。顶部「推荐」和「我的」是独立入口。「头像」仍按账号预览/固定菜单路径单独核对。当「我的」目标主页的子区或返回路径无实现依据时，保留待核，不用 Cloudy 侧栏替代。

这里的 A/B/C 是实现来源。A 直接接回 Cloudy 指定函数，叠加用户明确选择的 Rhine 差异。B 按 Rhine 的 QML/C++ 迁移视觉与交互。C 是共用覆盖规则。一个组合界面可同时用到 A 和 C，表中写主类别。布局单位沿用源码 DIP/u。原版截图来自用户附件和历史测试窗口，部分为旧候选版本或夹具数据。「待补」表示缺同屏证据。历史截图用于定位版式和对照状态，实际效果以同条件真窗复测为准。

Go 状态是源码盘点。**缺失**为未发现等价入口或界面，**Cloudy 样式**为已有上游实现但原版表现仍不同，**部分一致**为部分能力或实现已找到但等价性未证实。**一致**留给并排验证通过的条目。具有同名按钮、接口或效果的界面仍须分别验证位置、视觉、触发时机与返回行为。

- **原版 A 类做了一半的边界**。C 类已明确的自定义一律保留。歌词惯性、舞台引导、安静评论等先按固定 Cloudy 源回退。出现两版都能工作且差异无来源记录的 A 项时，将两边入口与动效并排再提问。
- **「我的」已确认**。S02 的入口方向已定。原型未完成，后续以个人主页对应 QML/设计决策补细节。现有自建库仍由头像菜单访问。
- **待补现场证据**。风格选择浮层、手机/邮箱登录及若干细分状态缺对应截图，现有记录仅说明源码状态。按里程碑在可控副本用相同尺寸、账号状态和素材补证。历史截图和原版实际显示冲突时记录 Qt 版本与对应入口。

## 评审与验证边界

M9 当前实现、三档离屏截图和仍待验收的差异见 [M9 外壳迁移记录](rhine-m9-shell.md)。外壳相关行保留「部分一致」，待并排实测后更新。

- M9 先做 S 系列：顶部导航、头像入口、底部播放栏和关闭顺序。960/1280/1920 DIP 并排比对，验证所有入口与空闲 0 帧。
- M10 按 H01–H12 验收。用 960/1280/1600/1920/2560 DIP 对比同主题、登录状态和相同内容：列宽、文字、间距、玻璃、悬停、播放/切换以及空、失败、重读。历史夹具与真实账号验证分开记录。
- M11 起按需求顺序逐单元完成，以真窗截图与输入测试确认每行。首开选歌墙跟踪暂搁，见 [M7 实测](rhine-m7-performance.md)。标准版复测首开 105.2 fps、p95 11.0 ms，尚未达到 ≥120 fps、p95 ≤8.3 ms。该轮切歌最慢 9.7 ms、15 秒空闲 0 帧、常驻工作集 176.70–196.78 MB。这些是历史数据，M8 没有新增帧或内存测量。
- 评审和修订用上表 ID。按 v2，在用户说「清单定了」前停在 M8。
