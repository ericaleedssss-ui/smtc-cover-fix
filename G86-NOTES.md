# G86 shared now-playing surface

The existing ArchiveReading owns the same original LiquidGlass surface and bounds. NowPlayingPanel is content, not another glass card. Playing a track requests this presentation without replacing the current browsing selection. A directory stays open while playing; returning home exposes the current player's track. Explicit column/record browsing returns to archive information. The existing full song details and lyric page remain accessible through the footer cover/title and the quiet detail link.

## Navigation and actual operations

- Discovery song entries play through the existing player with their real queue provenance and return to archive presentation. Search result and profile song entries use the same lightweight route. Playlist rows now single click without opening details, and double click to play; selection mode, artist/album links, context menus and explicit cover play remain. Native album/artist/podcast track rows similarly double click through music:play-row.
- followPlayback retains archive and directory information for passive transport changes; explicit footer/detail navigation sets the music frame to detail before following, fixing the old guard's interference with deliberate navigation. Roaming is exempt.
- Four compact controls: comments first, shared real heart artwork/state, share, more. More offers the existing collection picker, details, official source and return to browse information. A new playing scope in PlaylistMagazine captures the actual playing song, then reuses its existing share/collect implementations and immutable collection write selection. No duplicate write client or success simulation. Unknown heart state is explicit.
- Comment counts reuse the footer's identity-guarded server result. Artist avatars and cover pixels use Host.loadCover's allowlist, bounded async decoding and cache. Artist details fall back to /artists. Album metadata reuses the existing detail adapter/cache; actual release date and tags are shown only when supplied. Missing dates/styles stay unavailable.

## Motion and lyrics

- Original artwork is cropped to a transparent circular PNG once per loaded image (512px). The circular image rotates within a fixed inclined plane (48 degrees, slight in-plane tilt), at 40 seconds/revolution. No turntable base or tonearm.
- One declarative animation phase drives three staggered, thin concentric rings using transform and opacity. Motion is driven by real playing/pause/loading/failed/visible/reduced-motion state, NOT audio analysis or actual beat detection. Pause preserves the rotation angle, hides ring activity gently; hidden/reduced motion does not keep advancing. No high-frequency JS timer or animated blur.
- Lyrics reuse MusicPlayer.lyrics' document, index and offsets. A bounded ListView shows timed text/translations, small top/bottom fades, row hover/time stamps and validated seek on click. Wheel/touch browse only this viewport; follow can be resumed explicitly. Rows are rebuilt only when the lyric document changes, not on every playback update. There is no second progress bar.

## Validation and limits

Production NowPlaying compiled and ran against asynchronous domain fixtures: genuine circular alpha pixels, artist and album metadata, shared operations, known likes, pause, offset-correct seek and stale-track/lyric isolation. Existing production PlaylistMagazine model checks additionally verify current-playing-song share and collection capture rather than the browsed album. Actual QML software/OpenGL runs verify four window ratios, persistent original glass identity, tilt/rotation/pause/hidden stop, lyric scroll/follow/seek, track changes, controls and menu entry. Existing detail/collection QML regressions include a real single-click vs double-click row check. The real followPlayback function is compiled and exercised for archive, directory, detail and roaming. Changed production C++ files also pass syntax checks against real headers (opaque device backend; full multimedia compilation remains Windows CI).

Windows native UI QA uses the actual now-playing component after discovery playback and verifies shared-glass identity. Full Windows build/packaging outcome is reported separately. Online account writes, live provider metadata availability, long-running playback and physical Windows GPU performance cannot be claimed from offline fixtures. Existing server-side collection flow remains responsible for actual write confirmation and errors. No fabricated genre, date, comments or audio beat data.
