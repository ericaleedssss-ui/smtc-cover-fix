# G82 — archive content polish and album playback

Scope follows the user's final instruction: preserve all cover-switch animations while completing the remaining archive-content changes. RecordStack.qml, the shared original glass, panel geometry, FM and footer are unchanged.

The NetEase /album detail response returns songs without playlist.trackIds. The old adapter built its queue only from the third tuple field, so an album could show a nonzero track count yet have no playable queue, track preview or total duration. Normalize album IDs from the real parsed songs in API order. The archive adapter also handles older album tuples whose ID array is empty. Play/shuffle/append and Tab preview now share these IDs; deferred playlist IDs remain complete. Incomplete data is distinguished from a genuine empty collection. Missing durations are supplemented through the existing songs request and replace partial metadata rather than being discarded by first-wins deduplication. Total duration remains unknown if the service cannot provide complete durations.

Identity metadata preserves real artist image URLs. The adapter uses creatorAvatar/artist avatar, falling back to the existing authenticated /user/detail or /artists query when necessary, with selection/account guards and a public avatar URL cache. Unknown images use the existing user-outline design, never an album cover. Identity clicks route to the actual creator or primary artist.

The content layout has a stronger title, readable description/metadata and aligned circular avatars. Buttons use the user's original three PNG assets, copied byte-for-byte and alpha-tinted in the UI to the active theme. Play, shuffle, collect and more share button height, spacing, icon alignment and feedback. Clicking the title opens existing playlist/album details. Shortcut hints show Enter/Space/F on the left and Tab on the right; arrows and wheel still work but no longer appear as hints. Description and track regions consume wheel input even at their limits; visible scrollbars are removed while scrolling/list fades remain. The cover region retains the previous switching behavior and motion.
