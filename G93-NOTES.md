# G93 — draw a visible wide record and a refined upper-right tonearm

## Direction and scope

The G92 outer rim was too narrow and its screen-space fade erased it as it reached the lyrics. This revision deliberately presents a visible translucent physical disc through the middle/lyric region. G88 artwork dimensions, centre/rightward placement and tilt stay unchanged. The original glass, lyrics, actions, metadata, library/detail UI, playback/navigation and APIs are retained.

- `maintained/Qt/qml/NowPlayingPanel.qml`: outer diameter becomes 1.50 times discSize, while compensating the inset preserves artwork width exactly at discSize − 8 units. Replace the barely visible base with a real broad annular surface. Supply the actual cover-label radius to both the surface and groove/gloss shader, so texture extends across the whole expanded annulus. The record still crops at the existing glass bounds.
- `maintained/Qt/shaders/recordAtmosphere.frag`: broad translucent warm-grey vinyl pigment, fine radial grooves, bevel and a satin reflection give the annulus a body. Shared focal fading remains but does not erase the region behind lyrics: it retains partial alpha across the middle and softens toward the left. Sheen, rim, shadow and the rest of the image still use the same composition. Remove the former coarse procedural tonearm branches. Neutral white layered light and rounded glass clipping remain.
- `maintained/Qt/qml/RecordTonearm.qml` (new): a cached vector Canvas with a curved satin-metal shaft, darker underside/narrow highlight, radial bevel on the pivot, spindle, rounded cartridge, recessed seams, stylus and graduated contact-shadow strokes. Paint on size/theme changes; playback uses a transform of the cached drawing rather than repainting paths every frame. No additional dependency or high-frequency timer. Pivot is attached to the glass's upper-right corner at roughly 24 units from either edge, independently of record bounds. Preserve matching perspective and the pause/playing pose transition.
- `scripts/enable-g93.py` and `scripts/apply-maintained.py`: install/register the new QML component in the existing module using explicit UTF-8. No native business logic changes.
- `scripts/test-g86-qml.py`: compile/load the new component, verify unchanged G88 cover size and a genuinely wider rim, actual upper-right pivot coordinates, preserved pause state, clipping and continuous assembled visibility through the middle. The prior requirement that the left-middle composition disappear is intentionally replaced by the user's revised requirement that the wide disc remain visible behind lyrics.
- `.github/workflows/build-smtc.yml`: readable G93 labels and artifact name only. Embedded patches unchanged.

## Actual validation

Inspected both reference PNGs and five frames extracted from the supplied recording. Inspected actual rendered playing/paused and two phase frames after the changes. Deterministic concentric offline test artwork is used only in QA, never installed as replacement cover art.

The actual OpenGL RHI QML checks passed: four layouts and exact G88 cover geometry, expanded annulus, stationary platter/artwork-only spin, upper-right pivot, play/pause/hidden behavior, same glass object, lyrics wheel/seek/follow, current track updates, existing like/comment/share/More/collection/detail/album actions and global now-playing shortcut. Shader compilation covers GLSL, HLSL and MSL. The real framebuffer white-on-black composition probe now reads 103/179/254/195 at normalized x=.35/.50/.74/.99, replacing G92's 0/48/244/135. This confirms that the middle/left area remains visible rather than being cut away. Right rounded-corner clipping still passes. Lyrics are drawn above the record and remain outside the focal blur.

Clean source generation, protected-original/source identity verification, release bytecode compilation of RecordTonearm/NowPlayingPanel/integrated Main, patch CRC/SHA and diff checks passed. No redundant live API or unrelated animation tests were rerun. Full Windows compilation, native integrated UI, packaging, live artwork and physical-machine visual/performance acceptance remain pending. This records actual local checks, not a claim of exact subjective visual acceptance.
